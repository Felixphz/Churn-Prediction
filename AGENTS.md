# AGENTS.md — Churn Prediction Platform

## Layout (non-obvious)
- `backend/` — FastAPI app. Entrypoint: `backend/app/main.py`. Routers: `app/routers/` (all prefixed `/api/v1/*`; retrain routes live in `pipeline.py` under `/api/v1/retrain*`).
- `backend/scripts/` — `retrain.py` (monthly GridSearchCV pipeline), `seed_customers.py` and `init_training_db.py`. `backend/app/utils/` holds the real inference code (`preprocessor.py`, `model_predictor.py`, `batch_predictor.py`).
- `backend/retrainer/` — separate service (own `Dockerfile`, build context `./backend`, reuses `app/` + `scripts/`): APScheduler cron + FastAPI on `:8001` (`/trigger`, `/health`). **Local docker-compose only**; production retrain runs on GitHub Actions (`.github/workflows/monthly-retrain.yml`, cron day=1 02:00 UTC + `workflow_dispatch`).
- `ml_pipeline/` — notebooks (`eda`, `data_preprocessing`, `model_training`) + `src/data_ingestion.py` only. No training scripts here; production training is `backend/scripts/retrain.py`.
- `dashboard/` — Streamlit `app.py`. `infra/` — Dockerfiles for postgres + mlflow. Spec: `docs/BACKEND_REQUIREMENTS.md` (drifts from code; code wins).

## Run / verify
- Canonical: `docker compose up --build` (postgres `:5432`, api `:8000`, dashboard `:8501`, mlflow host `${MLFLOW_PORT:-5001}` → container `:5000`, retrainer `:8001` internal only).
- Container boot order is enforced: `backend/entrypoint.sh` runs `alembic upgrade head` → `python scripts/seed_customers.py` (skipped when `SEED_ON_STARTUP=false`) → `python scripts/init_training_db.py` (when `TRAINING_DATABASE_URL` is set) → `uvicorn app.main:app`. Don't replace with bare `uvicorn` in Docker.
- Local API (no Docker): run Postgres, copy `backend/.env.example` → `backend/.env` (it uses `localhost`; root `.env.example` uses Docker hostnames `postgres`/`mlflow`), then from `backend/`: `alembic upgrade head && uvicorn app.main:app --port 8000`.
- New migration from `backend/`: `alembic revision --autogenerate -m "<msg>"` (`alembic/env.py` reads `DATABASE_URL` from settings and imports all models). Alembic only covers the operational DB; the training DB schema is `create_all` in `init_training_db.py`.
- `infra/postgres/init.sql` creates `churn_training` only on a fresh `pgdata` volume: `docker compose down -v` or create it by hand.
- No tests, lint, typecheck, or CI exist (`pytest`/`httpx` are in `backend/requirements.txt` but there are zero test files).

## Gotchas — read before touching ML/DB code
- `*.csv`, `*.joblib`, `*.pkl` are gitignored. Three git-absent files break things silently:
  1. `ml_pipeline/data/raw/WA_Fn-UseC_-Telco-Customer-Churn.csv` — generate via `python ml_pipeline/src/data_ingestion.py` (kagglehub download); `seed_customers.py` fails without it.
  2. Model loading is **MLflow Registry-based**: `ModelLoader.get_model()` loads `models:/${REGISTRY_MODEL_NAME}@${MODEL_ALIAS}` (defaults `churn-model@production`) via `MLFLOW_TRACKING_URI` — no local joblib. Nothing registered = 500 with a clear error. Bootstrap once per environment: `python backend/scripts/register_initial_model.py`. MLflow server must be reachable at first predict (lazy load, cached in memory; auto-reloads within `MODEL_REFRESH_TTL_SECONDS`=30 when the alias points to a new version — a failed alias check keeps serving the cache). `retrain.py` registers + promotes the alias when improved. SHAP picks an explainer by model type (`TreeExplainer` → `LinearExplainer` → `PermutationExplainer`); if none works, prediction still returns with `shap_available: false` instead of a 500.
  3. The resampled notebook CSVs are **not** used by `run_retrain()` anymore (see two-database rule below). MLflow logging failure is caught and non-fatal; fewer than `RETRAIN_MIN_SAMPLES` training rows is fatal.
- Preprocessor contract (`backend/app/utils/preprocessor.py`): replicates `pd.get_dummies(drop_first=True)` from `data_preprocessing.ipynb` → exactly 30 features in `EXPECTED_FEATURE_NAMES`. Keep in sync with the notebook; never re-derive encoding independently.
- Case mismatch is intentional: DB/schemas use `snake_case` (`senior_citizen`), preprocessor expects notebook `CapitalCase` keys (`SeniorCitizen`, `MonthlyCharges`, …). Use `customer_to_record()` in `preprocessor.py` when adding callers.
- **Two databases, never mixed.** `DATABASE_URL` (operational, Neon in prod): unlabeled `customers` used for inference, `predictions`, `retrain_history`, `model_registry`. `TRAINING_DATABASE_URL` (separate Neon project in prod): `training_samples` with **confirmed outcomes only** — Kaggle history (`label_source=historical`) + `POST /api/v1/outcomes` (`observed`). Never write predictions as labels. `prediction_id`/`predicted_probability` on a sample are for predicted-vs-actual monitoring, never features. A churned outcome sets `customers.active=false` (batch skips it). Samples with `retention_action=true` are kept but excluded from training unless `RETRAIN_INCLUDE_TREATED=true` (their outcome is confounded by the intervention). Feature snapshot is taken at outcome time, not prediction time.
- Threshold default is `0.30`, not `0.5` (`MODEL_THRESHOLD`, `DEFAULT_MODEL=LogisticRegression`). Retrain only promotes when F1 exceeds active model by `RETRAIN_MIN_IMPROVEMENT` (default `0.01`).
- The API schedules nothing. `POST /api/v1/retrain/trigger` returns 409 if the latest `retrain_history` is `running` and younger than `RETRAIN_STALE_HOURS`; otherwise it dispatches the GitHub workflow when `GITHUB_TOKEN` + `GITHUB_REPO` are set (fine-grained PAT, Actions read/write), else proxies to `RETRAIN_SERVICE_URL` (local). `GET /api/v1/retrain/top-models` queries MLflow directly. GitHub disables scheduled workflows after 60 days without repo activity (public repos); re-enable in the Actions tab. Workflow secrets: `DATABASE_URL`, `TRAINING_DATABASE_URL`, `MLFLOW_TRACKING_URI` (+ optional `MLFLOW_TRACKING_USERNAME`/`PASSWORD`).
- Each retrain logs every candidate as an MLflow run (model + `cv_f1_macro` + `test_*`) in experiment `churn_prediction`, then `prune_runs()` deletes all runs outside the top `TOP_K_MODELS` (default 5) by `cv_f1_macro`, never the `@production` one. `delete_run` is a soft delete; free artifact disk with `mlflow gc --backend-store-uri ...` in the mlflow container.
- `dashboard/app.py` reads `API_URL` from env (default `http://api:8000` for Docker); local/Streamlit Cloud must set it. Timeouts: GET 60s, predict 90s, batch 180s, retrain 90s.
